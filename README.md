# ربات تلگرام دانلود اینستاگرام + یوتیوب

ربات پایتونی که لینک پست/ریلز/استوری اینستاگرام یا ویدیو/شورتز یوتیوب
رو می‌گیره، کیفیت‌های مختلف ویدیو رو با **حجم دقیق** نشون می‌ده تا کاربر
انتخاب کنه، گزینه‌ی «فقط صدا» هم داره، و حین دانلود یه **نوار پیشرفت
زنده** (درصد + حجم دانلودشده/کل) نمایش می‌ده.

## پیش‌نیازها

1. **پایتون ۳.9 به بالا**
2. **ffmpeg** روی سیستم نصب باشه (برای merge کردن ویدیو/صدا و استخراج mp3):
   - لینوکس: `sudo apt install ffmpeg`
   - مک: `brew install ffmpeg`
   - ویندوز: از سایت ffmpeg دانلود و به PATH اضافه کن
3. یه توکن ربات تلگرام از **@BotFather**

## نصب

```bash
cd insta_bot
python -m venv venv
source venv/bin/activate   # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
```

## اجرا

```bash
export TELEGRAM_BOT_TOKEN="توکن-ربات-تو"
export AUDD_API_KEY="توکن-audd-تو"   # اختیاری - برای تشخیص آهنگ از روی صدا
python bot.py
```

روی ویندوز (PowerShell):
```powershell
$env:TELEGRAM_BOT_TOKEN="توکن-ربات-تو"
python bot.py
```

## استفاده

1. با ربات چت رو استارت کن (`/start`)
2. لینک پست/ریلز/استوری اینستاگرام، ویدیو/شورتز یوتیوب یا ویدیوی
   تیک‌تاک رو بفرست، **یا** دکمه‌ی «🎵 جستجوی موزیک» رو بزن
3. تامبنیل + توضیحات محتوا نشون داده می‌شه؛ از بین دکمه‌های کیفیت
   (هرکدوم با حجم دقیق، مثلاً `1080p - 24.3MB`) یکی رو انتخاب کن، یا
   دکمه‌ی «🎵 فقط صدا» رو بزن
4. یه نوار پیشرفت زنده می‌بینی که درصد، حجم دانلودشده/کل و سرعت رو
   نشون می‌ده
5. دانلود که تموم شد، فایل برات ارسال می‌شه

### جستجوی موزیک (لیست کامل + صفحه‌بندی)

روی دکمه‌ی «🎵 جستجوی موزیک» بزن و اسم آهنگ یا **فقط اسم خواننده** رو
بفرست:

- اول فقط تو **یوتیوب‌میوزیک** (کاتالوگ رسمی گوگل) می‌گردم؛ اگه فقط
  اسم خواننده بفرستی، همه‌ی آهنگ‌های شناخته‌شده‌اش از همونجا لیست
  می‌شه (برای خواننده‌های خارجی معمولاً کاتالوگ کاملیه)
- نتیجه‌ها ۱۰تا-۱۰تا صفحه‌بندی می‌شن؛ با دکمه‌های «◀️ صفحه قبل» و
  «▶️ صفحه بعد» بین صفحه‌ها جابه‌جا شو
- روی هر آهنگ که بزنی، همون دکمه‌های کیفیت/فقط‌صدا براش نشون داده
  می‌شه
- **اگه چیزی پیدا نشد یا نتایج کم بود** (مثلاً خیلی از آهنگ‌های فارسی
  تو یوتیوب‌میوزیک نیستن)، پایین لیست یه دکمه‌ی **«🔍 جستجو در
  یوتیوب»** هست؛ باهاش می‌تونی همون جستجو رو دستی تو یوتیوب عادی هم
  انجام بدی و نتایجش رو ببینی — دیگه خودکار مخلوط نمی‌شه، خودت تصمیم
  می‌گیری

سیستم امتیازدهی (برای فیچر «پیدا کردن آهنگ اصلی» که در ادامه توضیح
داده می‌شه) طوریه که نسخه‌ی رسمی/آفیشیال رو در اولویت می‌ذاره و
ریمیکس/کاور/لایو رو عقب می‌زنه (مگه خودت دنبال ریمیکس/کاور باشی).

> از اسپاتیفای امکان دانلود مستقیم فایل صوتی وجود نداره (استریم‌هاش
> DRM داره)، برای همین منبع دانلود همیشه یوتیوب/ساندکلاوده؛ ولی
> محتواش همونیه که تو اسپاتیفای/یوتیوب‌میوزیک هم پخش می‌شه.

### تمیزکاری بعد از ارسال و دکمه‌ی «🔗 لینک»

- بعد از ارسال موفق، پیام «در حال ارسال…» خودش پاک می‌شه
- اگه کاربر لینک فرستاده بود، پیام لینکش هم پاک می‌شه و به‌جاش زیر خود
  ویدیو/صدا یه دکمه‌ی شیشه‌ای **«🔗 لینک»** هست که با زدنش لینک اصلی باز می‌شه
- اگه ارسال با خطا تموم بشه، هیچ پیامی پاک نمی‌شه (که خطا رو ببینی و دوباره امتحان کنی)
- پاک کردن پیام کاربر تو چت خصوصی کار می‌کنه؛ تو گروه ربات باید ادمین باشه
  (اگه نشد، بی‌صدا نادیده گرفته می‌شه)

### ضد اسپم (تایمر ۲۰ ثانیه)

هر کاربر هر **۲۰ ثانیه** فقط یه درخواست جدید می‌تونه بده. دو شمارنده‌ی جدا داریم:

- **پیام درخواست** (لینک، پلی‌لیست، جستجوی موزیک، فرستادن فایل)
- **شروع کار** (زدن دکمه‌ی دانلود، استخراج صدا، پیدا کردن آهنگ)

پس لینک فرستادن و بعدش زدن دکمه‌ی دانلود به هم گیر نمی‌دن. ورق زدن صفحه‌های
پلی‌لیست/جستجو و دکمه‌ی «کارم تموم شد» تایمر ندارن. اگه کسی زودتر بفرسته،
ربات می‌گه چند ثانیه صبر کنه (حداکثر هر ۵ ثانیه یه بار، که خود پیام صبر کن اسپم نشه).
پیام‌های بی‌ربط (که لینک یا جستجو نیستن) تایمر رو مصرف نمی‌کنن.

مدت تایمر رو می‌شه با متغیر محیطی `REQUEST_COOLDOWN_SECONDS` عوض کرد
(پیش‌فرض ۲۰؛ عدد `0` تایمر رو خاموش می‌کنه).

### پلی‌لیست یوتیوب

لینک یه پلی‌لیست یوتیوب (همونی که `/playlist?list=...` داره) رو بفرست:

- اطلاعات پلی‌لیست (اسم، کانال، تعداد ویدیو، توضیحات) با تصویرش میاد
- ویدیوها **۵تا-۵تا** صفحه‌بندی می‌شن؛ زیر هر صفحه دکمه‌ی «▶️ صفحه بعد»
  (و تو صفحه‌های بعدی «◀️ صفحه قبل») هست
- روی هر ویدیو که بزنی، اطلاعات و تصویر همون ویدیو با دکمه‌های کیفیت/
  فقط‌صدا/پیدا کردن آهنگ میاد و می‌تونی دانلودش کنی؛ پیام پلی‌لیست سر
  جاش می‌مونه که بری سراغ ویدیوی بعدی
- آخر هر صفحه دکمه‌ی **«✅ کارم تموم شد»** هست: دکمه‌های شیشه‌ای بسته
  می‌شن ولی اطلاعات پلی‌لیست تو پیام می‌مونه

نکات: ویدیوهای خصوصی/حذف‌شده نادیده گرفته می‌شن و تعدادشون کنار تعداد
کل نوشته می‌شه. حداکثر ۳۰۰ ویدیوی اول هر پلی‌لیست خونده می‌شه.
لینک یه ویدیو که `&list=...` هم داره مثل قبل فقط همون یه ویدیو حساب
می‌شه؛ برای کل پلی‌لیست، لینک خود پلی‌لیست رو بفرست.

### ارسال خود فایل ویدیو (نه لینک)

اگه به‌جای لینک، خود کلیپ/ویدیو رو (مثلاً فایل یه ریلز) برای ربات
بفرستی، ربات می‌پرسه «چیکار کنم؟» با دو دکمه‌ی شیشه‌ای:

- **🎵 استخراج صدا**: صدای ویدیو رو mp3 می‌کنه و می‌فرسته
- **🎧 پیدا کردن آهنگ اصلی**: آهنگ ویدیو رو تشخیص می‌ده (کپشن با
  Gemini، بعد AudD/ACRCloud از روی صدا) و نسخه‌ی رسمیش رو با ویس
  می‌فرسته

نکات: اگه برای ویدیو کپشن بنویسی تشخیص دقیق‌تر می‌شه. سرور رسمی
تلگرام فقط اجازه‌ی دریافت فایل تا ۲۰ مگابایت رو می‌ده؛ برای فایل
بزرگ‌تر باید سرور محلی فعال باشه (`TELEGRAM_API_ID` و
`TELEGRAM_API_HASH`، بخش «سقف ۲ گیگ» پایین‌تر).

### پیدا کردن آهنگ اصلی یه ویدیو (زیر دکمه‌های کیفیت)

وقتی لینک یه ریلز/شورتز/ویدیو می‌فرستی، زیر دکمه‌های کیفیت یه دکمه‌ی
«🎵 پیدا کردن آهنگ اصلی ویدیو» هم هست. با زدنش، این مراحل رو به ترتیب
امتحان می‌کنه تا یکیشون جواب بده:

1. **متادیتای پلتفرم** — چک می‌کنه خود پلتفرم (معمولاً تیک‌تاک) اسم
   آهنگ رو تو متادیتاش داده یا نه
2. **Gemini** (هوش مصنوعی رایگان گوگل) — عنوان و کپشن ویدیو رو
   می‌خونه، حتی اگه فینگلیش یا فارسی باشه؛ خیلی وقتا خود کپشن اسم
   آهنگ رو داره. ریمیکس/کاور رو هم تشخیص می‌ده
3. **تشخیص از روی صدا (دو نقطه از ویدیو)** — یه تیکه از اول ویدیو رو
   می‌گیره و با **[AudD](https://dashboard.audd.io)** چک می‌کنه؛ اگه
   جواب نداد یه سرویس دوم به اسم **[ACRCloud](https://console.acrcloud.com)**
   رو هم امتحان می‌کنه؛ اگه بازم جواب نداد و ویدیو به‌اندازه‌ی کافی
   طولانی باشه، یه تیکه از وسط ویدیو رو هم می‌گیره و دوباره هر دو
   سرویس رو امتحان می‌کنه (چون گاهی اول ویدیو فقط حرف زدنه، نه آهنگ)

بعد از پیدا کردن نسخه‌ی رسمی، **خودکار هم ویدیو هم نسخه‌ی صوتیش** رو
برات می‌فرسته — نیازی به انتخاب دستی کیفیت نیست. نسخه‌ی صوتی با اسم
تمیز و درست آهنگ (نه اسم خام فایل یوتیوب) تگ‌گذاری می‌شه که تو
تلگرام قشنگ نشون داده بشه. اگه نسخه‌ی رسمی پیدا نشه، لااقل اسم
خواننده‌ای که شناسایی شده رو بهت می‌گه تا خودت دستی از
«🎵 جستجوی موزیک» امتحان کنی.

برای مرحله‌ی ۲ (بررسی کپشن با هوش مصنوعی) نیاز به یه کلید **رایگان**
از Gemini داری:

1. برو [aistudio.google.com](https://aistudio.google.com) و با یه
   حساب گوگل وارد شو
2. از بخش **Get API key** یه کلید بساز (کاملاً رایگانه، فقط محدودیت
   تعداد درخواست روزانه داره که برای این کار کافیه)
3. متغیر محیطی `GEMINI_API_KEY` رو باهاش ست کن (لوکال یا روی Railway
   در تب Variables)

> ⚠️ نکته درباره‌ی چت‌جی‌پی‌تی: فقط نسخه‌ی وب چتش رایگانه؛ API اش
> پولیه، برای همین این پروژه از Gemini استفاده می‌کنه که API رایگان
> واقعی داره.

برای مرحله‌ی ۳ (تشخیص از روی صدا) دو تا سرویس رو می‌تونی تنظیم کنی
(هرکدوم اختیاری، ولی داشتن هردوتا دقت رو بالاتر می‌بره):

**AudD** (اولین سرویس امتحان‌شده):
1. برو [dashboard.audd.io](https://dashboard.audd.io) و ثبت‌نام کن
2. توکن API رو بگیر
3. متغیر محیطی `AUDD_API_KEY` رو باهاش ست کن

**ACRCloud** (سرویس دوم، وقتی AudD جواب نده امتحان می‌شه):
1. برو [console.acrcloud.com](https://console.acrcloud.com) و ثبت‌نام کن
2. یه پروژه از نوع **Audio & Video Recognition** بساز
3. از پروژه‌ت `Host`، `Access Key` و `Access Secret` رو بردار
4. سه متغیر محیطی ست کن: `ACR_HOST`، `ACR_ACCESS_KEY`، `ACR_ACCESS_SECRET`

هیچ‌کدوم از این کلیدها اجباری نیست — بدون‌شون هم ربات کار می‌کنه، فقط
دقت تشخیص کمتر می‌شه.

بدون این توکن، دکمه فقط برای ویدیوهایی کار می‌کنه که خودشون متادیتای
آهنگ رو دارن (مثل بیشتر ویدیوهای تیک‌تاک)؛ برای بقیه پیام می‌ده که
توکن تنظیم نشده.

## محدودیت‌ها و نکات مهم

- **سقف حجم فایل — راه‌اندازی سقف ۲ گیگ:** پروژه از قبل یه
  [Local Bot API Server](https://github.com/tdlib/telegram-bot-api)
  رو تو `Dockerfile` می‌سازه (سقفش تا ۲ گیگ میشه به‌جای ۵۰ مگ). برای
  فعال‌سازیش:
  1. برو [my.telegram.org](https://my.telegram.org) و با شماره‌ی
     تلگرامت لاگین کن
  2. از بخش **API Development Tools** یه اپ بساز (اسم و توضیح دلخواه)
     و `api_id` و `api_hash` رو یادداشت کن
  3. روی Railway (یا هرجا دیپلوی می‌کنی) دو متغیر محیطی اضافه کن:
     - `TELEGRAM_API_ID` = همون api_id
     - `TELEGRAM_API_HASH` = همون api_hash
  4. همین! `start.sh` خودش موقع استارت سرور محلی رو با این مقادیر بالا
     میاره و ربات خودکار بهش وصل می‌شه (`MAX_TELEGRAM_UPLOAD_MB` هم
     خودکار می‌ره رو ۲۰۰۰)
  - اگه نمی‌تونی متغیر محیطی ست کنی، می‌تونی همین دو مقدار رو تو یه فایل
    به اسم `local_secrets.sh` (کنار `start.sh`) بذاری:
    ```
    export TELEGRAM_API_ID="123456"
    export TELEGRAM_API_HASH="abcdef..."
    ```
    ⚠️ این فایل رمز داره؛ فقط تو ریپوی **Private** آپلودش کن.
  - `start.sh` اول چک می‌کنه سرور محلی واقعاً بالا اومده؛ فقط اگه سالم بود،
    طبق مستندات تلگرام ربات رو از سرور ابری `logOut` می‌کنه (لازمه تا
    آپدیت‌ها به سرور محلی برسن). اگه سرور محلی بالا نیومد (مثلاً api_id
    یا api_hash اشتباه بود)، خودکار به سرور رسمی برمی‌گرده و ربات از کار
    نمی‌افته. بعد از logOut تا ۱۰ دقیقه نمی‌شه ربات رو دوباره با سرور
    ابری اجرا کرد.
  - برای فایل‌های بزرگ، سرور محلی با `--local` بالا میاد و ربات (`local_mode`)
    به‌جای آپلود کل فایل از طریق HTTP، فقط **مسیر فایل** رو بهش می‌ده تا خود
    سرور از دیسک بخونه. این‌جوری فایل چند صد مگی تو رمِ ربات لود نمی‌شه
    (قبلاً می‌تونست ربات رو با کمبود حافظه از کار بندازه). تایم‌اوت‌های ارسال
    هم بلند شدن (۳۰ دقیقه) و ربات همزمان به چند درخواست جواب می‌ده، پس تا
    وقتی یه فایل بزرگ داره ارسال می‌شه، ربات بقیه رو هم جواب می‌ده
  - اگه این دو متغیر رو ست نکنی، ربات مثل قبل از سرور رسمی تلگرام
    (سقف ۵۰ مگ) استفاده می‌کنه — هیچ‌چیز خراب نمی‌شه
  - چون سرور محلی و ربات تو یه container کنار همدیگه‌ان، ترافیک فایل‌ها
    از شبکه‌ی عمومی رد نمی‌شه؛ سریع‌تر هم هست
  - ساخت `telegram-bot-api` از سورس حدود ۵ تا ۱۵ دقیقه به زمان build
    اضافه می‌کنه (فقط یه‌بار، موقع دیپلوی)
- **پست‌های خصوصی یا خطای «Sign in to confirm you're not a bot»:**
  یوتیوب (و گاهی اینستاگرام) روی سرورهای ابری مثل Railway درخواست‌ها
  رو مشکوک تشخیص می‌ده و کوکی می‌خواد. راه‌حل:
  1. با یه اکستنشن مرورگر مثل **"Get cookies.txt LOCALLY"**، وقتی تو
     یوتیوب/اینستاگرام لاگین هستید، فایل `cookies.txt` رو export
     بگیرید
  2. **اجرای لوکال:** مسیر فایل رو در متغیر محیطی `COOKIES_FILE` بدید
  3. **روی Railway (چون نمی‌شه مستقیم فایل آپلود کرد):** محتوای فایل
     رو base64 کنید و در یه متغیر محیطی به اسم `COOKIES_FILE_B64`
     بذارید:
     ```bash
     base64 -w0 cookies.txt   # لینوکس/مک - خروجی رو کپی کنید
     ```
     (ویندوز PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cookies.txt"))`)
     بعد این مقدار رو در Railway → Variables → `COOKIES_FILE_B64` بذارید.
     ربات موقع استارت خودش دیکودش می‌کنه و به‌عنوان کوکی استفاده می‌کنه.
  - ⚠️ کوکی‌ها اطلاعات حساب شما رو دارن؛ هرگز فایل `cookies.txt` رو
    مستقیم پوش نکنید روی گیت‌هاب (تو `.gitignore` هست). فقط مقدار
    base64 شده رو به‌صورت متغیر محیطی (نه توی کد) بذارید.
  - کوکی‌ها بعد از مدتی منقضی می‌شن؛ اگه دوباره همین خطا اومد، یه
    export تازه بگیرید.
  - ربات کوکی رو **همیشه** نمی‌فرسته؛ اول هر درخواست رو بدون کوکی
    امتحان می‌کنه (مثل یه کاربر عادی) و فقط اگه سایت مشخصاً خطای
    «Sign in to confirm you're not a bot» بده، همون یه‌بار با کوکی
    دوباره تلاش می‌کنه. این‌جوری کوکی روی اینستاگرام یا ویدیوهای
    عادی یوتیوب که نیازی بهش ندارن تأثیر نمی‌ذاره.
- **خطای «The page needs to be reloaded» (فرق داره با خطای کوکی):**
  از اواخر ۲۰۲۵ یوتیوب یه چالش جاوااسکریپتی جدید گذاشته و `yt-dlp`
  برای حلش به یه JS runtime به اسم **Deno** نیاز داره؛ بدون اون دقیقاً
  همین خطا رو می‌ده. پروژه الان به‌صورت پیش‌فرض `yt-dlp[default]` +
  پکیج pip به اسم `deno` رو نصب می‌کنه (تو `requirements.txt`) که این
  مشکل رو حل می‌کنه. اگه بازم دیدیدش:
  1. مطمئن بشید آخرین نسخه‌ی `requirements.txt` رو پوش کردید
  2. روی Railway یه **Redeploy** دستی بزنید (بدون کش قدیمی)
  3. توی **Logs** مرحله‌ی build دنبال نصب موفق `deno` و `yt-dlp` بگردید
- **خطای «HTTP Error 403: Forbidden» موقع دانلود:** یعنی `yt-dlp`
  اطلاعات ویدیو رو گرفته ولی یوتیوب خود فایل رو نداده (معمولاً چون IP
  سرورهای ابری مشکوکه، کوکی منقضی شده، یا کلاینتی که PO Token می‌خواد).
  ربات خودش به ترتیب این تلاش‌ها رو انجام می‌ده: ۱) بدون کوکی ۲) با
  کوکی (اگه `COOKIES_FILE_B64` ست باشه) ۳) با کلاینت جایگزین
  `android_vr`. اگه بازم شکست خورد:
  1. یه export تازه از کوکی یوتیوب بگیر و `COOKIES_FILE_B64` رو عوض کن
  2. تو **Logs** رایلوی، خط اول استارت رو ببین (`yt-dlp ... | deno: ...`):
     اگه جلوی `deno` نوشته `NOT FOUND`، یعنی JS runtime نصب نشده و
     همین باعث ۴۰۳ می‌شه (باید `requirements.txt` رو مطمئن بشی پوش شده)
  3. اگه همچنان ادامه داشت، راه‌حل‌های قوی‌تر پراکسی/IP مسکونی یا راه
     انداختن یه PO-Token provider جداست
- **تغییرات پلتفرم‌ها:** یوتیوب/اینستاگرام/تیک‌تاک مرتب ساختار
  سایتشون رو عوض می‌کنن، پس ممکنه گاهی نیاز باشه `yt-dlp` رو آپدیت
  کنید: `pip install -U "yt-dlp[default]"`
- **مسئولیت استفاده:** این ابزار رو فقط برای محتوای خودتون یا محتوایی
  که اجازه دارید دانلود کنید به کار ببرید؛ نقض کپی‌رایت یا قوانین
  پلتفرم‌ها مسئولیتش با کاربره.

## دیپلوی روی گیت‌هاب + Railway

### ۱. آپلود روی گیت‌هاب

```bash
cd insta_bot
git init
git add .
git commit -m "Instagram downloader telegram bot"
git branch -M main
git remote add origin https://github.com/USERNAME/insta-bot.git
git push -u origin main
```

⚠️ فایل `cookies.txt` (اگه استفاده کردید) رو **هرگز** پوش نکنید؛ توی
`.gitignore` گذاشتمش که به‌صورت پیش‌فرض ایگنور بشه.

### ۲. دیپلوی روی Railway

پروژه یه `Dockerfile` داره که `ffmpeg` رو به‌صورت مطمئن نصب می‌کنه
(روش Nixpacks گاهی ffmpeg رو درست نصب نمی‌کنه، برای همین از Docker
استفاده کردیم).

1. وارد [railway.app](https://railway.app) بشید و با گیت‌هاب لاگین کنید
2. **New Project → Deploy from GitHub repo** رو بزنید و ریپوی خودتون رو انتخاب کنید
3. Railway باید خودش `Dockerfile` رو تشخیص بده و ازش استفاده کنه. اگه
   تشخیص نداد: برید تو **Settings → Build** پروژه و **Builder** رو
   دستی روی **Dockerfile** بذارید
4. توی تب **Variables** پروژه، متغیر محیطی زیر رو اضافه کنید:
   - `TELEGRAM_BOT_TOKEN` = توکن ربات از BotFather
   - (اختیاری) `COOKIES_FILE_B64` برای رفع خطای «Sign in to confirm
     you're not a bot» یا دانلود محتوای خصوصی (توضیح کامل در بخش
     محدودیت‌ها)
5. چون ربات با **polling** کار می‌کنه (نه webhook)، نیازی به دامنه یا
   پورت باز نیست؛ Railway با فایل `Procfile` (`worker: python bot.py`)
   می‌فهمه باید همیشه در حال اجرا نگهش داره
6. دیپلوی که تموم شد، توی تب **Logs** باید پیام «ربات در حال اجراست...»
   رو ببینید — یعنی ربات آنلاینه

### نکات دیپلوی روی Railway

- پلن رایگان Railway محدودیت ساعت مصرف داره؛ برای اجرای ۲۴/۷ احتمالاً
  نیاز به آپگرید پلن دارید
- اگه فایل‌های حجیم (بالای ۵۰ مگ) رد و بدل می‌شه، فضای دیسک موقت
  Railway هم محدوده؛ کد فایل‌های دانلودشده رو بعد از ارسال پاک می‌کنه
  (`shutil.rmtree`) پس مشکلی برای فضا پیش نمیاد
- هر بار که به `main` پوش کنید، Railway خودکار ری‌دیپلوی می‌کنه

### اگه بازم خطای ffmpeg گرفتید

1. مطمئن بشید فایل `Dockerfile` واقعاً توی ریپو پوش شده (`git status`)
2. توی Railway، تب **Settings → Build** پروژه رو چک کنید که Builder
   روی **Dockerfile** باشه، نه Nixpacks
3. یه **Redeploy** دستی بزنید (گاهی دیپلوی قبلی cache شده)
4. توی **Logs** مرحله‌ی build، دنبال خط `Setting up ffmpeg` بگردید تا
   مطمئن بشید واقعاً نصب شده
