# venv\Scripts\activate

export TELEGRAM_BOT_TOKEN="YOUR_TELEGRAM_BOT_TOKEN"

python bot.py

## 🎵 جستجوی موزیک

با انتخاب دکمه **🎵 جستجوی موزیک** می‌توانید نام آهنگ یا فقط نام خواننده
را ارسال کنید.

-   جستجو ابتدا در **YouTube Music** انجام می‌شود.
-   اگر نام خواننده را وارد کنید، آهنگ‌های شناخته‌شده او جستجو می‌شوند.
-   نتایج ۱۰تایی صفحه‌بندی می‌شوند.
-   با دکمه‌های صفحه قبل و بعد بین نتایج جابه‌جا شوید.
-   با انتخاب هر آهنگ، گزینه‌های کیفیت و فقط صدا نمایش داده می‌شوند.
-   اگر نتیجه کافی نبود، دکمه **🔍 جستجو در یوتیوب** امکان جستجوی دستی
    در YouTube را می‌دهد.
-   سیستم امتیازدهی نسخه رسمی را به ریمیکس، کاور و اجرای زنده ترجیح
    می‌دهد؛ مگر اینکه خودتان دنبال آن نسخه‌ها باشید.

> دانلود مستقیم فایل صوتی از Spotify پشتیبانی نمی‌شود؛ استریم‌های Spotify
> دارای DRM هستند. منبع دریافت فایل، YouTube یا SoundCloud است.

## 🎼 پیدا کردن آهنگ اصلی ویدیو

برای لینک ریلز، Shorts یا ویدیو، دکمه **🎵 پیدا کردن آهنگ اصلی ویدیو**
در کنار گزینه‌های کیفیت نمایش داده می‌شود. سیستم به ترتیب این روش‌ها را
بررسی می‌کند:

1.  **متادیتای پلتفرم:** بررسی اطلاعات آهنگ در متادیتای ویدیو؛ این روش
    به‌خصوص برای برخی ویدیوهای TikTok مفید است.
2.  **Gemini AI:** تحلیل عنوان و کپشن ویدیو، حتی در متن فارسی یا
    فینگلیش.
3.  **AudD:** تشخیص موسیقی از روی بخشی از صدای ویدیو.
4.  **ACRCloud:** سرویس جایگزین در صورت ناموفق بودن AudD.
5.  **نمونه دوم صدا:** اگر بخش ابتدایی ویدیو نتیجه ندهد و ویدیو به‌اندازه
    کافی طولانی باشد، بخش دیگری از میانه ویدیو بررسی می‌شود.

در صورت شناسایی موفق، ربات ویدیو و نسخه صوتی آهنگ را ارسال می‌کند. فایل
صوتی با نام و اطلاعات مرتب آهنگ تگ‌گذاری می‌شود. اگر نسخه رسمی پیدا نشود،
نام هنرمند شناسایی‌شده نمایش داده می‌شود تا بتوانید آن را از بخش جستجوی
موزیک پیدا کنید.

### راه‌اندازی Gemini

1.  وارد [Google AI Studio](https://aistudio.google.com) شوید.
2.  از بخش **Get API key** یک کلید API بسازید.
3.  مقدار آن را در متغیر `GEMINI_API_KEY` قرار دهید.

### راه‌اندازی AudD

1.  در [AudD Dashboard](https://dashboard.audd.io) ثبت‌نام کنید.
2.  توکن API را دریافت کنید.
3.  آن را در متغیر `AUDD_API_KEY` قرار دهید.

### راه‌اندازی ACRCloud

1.  وارد [ACRCloud Console](https://console.acrcloud.com) شوید.
2.  پروژه‌ای از نوع **Audio & Video Recognition** بسازید.
3.  مقادیر Host، Access Key و Access Secret را دریافت کنید.
4.  متغیرهای `ACR_HOST`، `ACR_ACCESS_KEY` و `ACR_ACCESS_SECRET` را تنظیم
    کنید.

> همه کلیدهای تشخیص موسیقی اختیاری‌اند. بدون آن‌ها قابلیت‌های اصلی دانلود
> همچنان کار می‌کنند، اما تشخیص آهنگ محدودتر خواهد بود.

## 📂 پلی‌لیست یوتیوب

لینک خود پلی‌لیست (دارای `/playlist?list=...`) را ارسال کنید.

-   نمایش نام، کانال، تعداد و توضیحات پلی‌لیست به همراه تصویر
-   صفحه‌بندی ویدیوها به‌صورت ۵تایی
-   نمایش اطلاعات هر ویدیو و گزینه‌های دانلود آن
-   امکان دانلود هر ویدیو بدون حذف پیام پلی‌لیست
-   دکمه **✅ کارم تموم شد** برای بستن دکمه‌های تعاملی
-   نادیده گرفتن ویدیوهای خصوصی یا حذف‌شده و نمایش تعداد آن‌ها
-   بررسی حداکثر ۳۰۰ ویدیوی اول پلی‌لیست

**نکته:** لینکی که مربوط به یک ویدیو است و فقط پارامتر `&list=...` دارد،
همچنان به‌عنوان یک ویدیو پردازش می‌شود. برای دریافت کل پلی‌لیست، لینک خود
پلی‌لیست را ارسال کنید.

## 🛡️ سیستم ضداسپم

به‌صورت پیش‌فرض هر کاربر هر **۲۰ ثانیه** فقط می‌تواند یک درخواست جدید ثبت
کند. دو شمارنده مستقل وجود دارد:

-   **پیام درخواست:** لینک، پلی‌لیست، جستجوی موزیک یا ارسال فایل
-   **شروع عملیات:** انتخاب دانلود، استخراج صدا یا پیدا کردن آهنگ

بنابراین ارسال لینک و سپس انتخاب کیفیت، بی‌دلیل با یکدیگر تداخل ندارند.
ورق زدن صفحات و دکمه «کارم تموم شد» مشمول تایمر نیستند. پیام‌های نامرتبط
نیز تایمر را مصرف نمی‌کنند.

برای تغییر زمان:

``` bash
export REQUEST_COOLDOWN_SECONDS=20
```

مقدار `0` تایمر را غیرفعال می‌کند.

## 🐳 سقف فایل تا ۲ گیگابایت با Local Bot API

پروژه در `Dockerfile` سرور رسمی [Telegram Bot
API](https://github.com/tdlib/telegram-bot-api) را از سورس می‌سازد. با
فعال کردن حالت محلی، سقف فایل می‌تواند تا ۲ گیگابایت افزایش یابد.

### فعال‌سازی

1.  وارد [my.telegram.org](https://my.telegram.org) شوید.
2.  از بخش **API Development Tools** یک اپلیکیشن بسازید.
3.  مقادیر `api_id` و `api_hash` را دریافت کنید.
4.  این دو متغیر را در محیط اجرا تنظیم کنید:

``` env
TELEGRAM_API_ID=YOUR_API_ID
TELEGRAM_API_HASH=YOUR_API_HASH
```

اسکریپت `start.sh` سرور محلی را هنگام اجرا راه‌اندازی می‌کند و در صورت
سالم بودن آن، ربات را به سرور محلی متصل می‌کند. مقدار
`MAX_TELEGRAM_UPLOAD_MB` نیز به‌صورت خودکار روی ۲۰۰۰ تنظیم می‌شود.

### نکات فنی

-   اگر سرور محلی راه‌اندازی نشود، ربات به API رسمی برمی‌گردد.
-   پس از اجرای `logOut` برای انتقال ربات به سرور محلی، تا ۱۰ دقیقه
    نمی‌توان همان ربات را دوباره با سرور ابری اجرا کرد.
-   در حالت `--local`، سرور محلی فایل را مستقیماً از مسیر دیسک می‌خواند و
    لازم نیست کل فایل در حافظه RAM ربات بارگذاری شود.
-   مهلت ارسال فایل‌های بزرگ تا ۳۰ دقیقه افزایش یافته است.
-   ربات می‌تواند هم‌زمان به درخواست‌های دیگر نیز پاسخ دهد.
-   چون سرور محلی و ربات در یک کانتینر قرار دارند، انتقال فایل بین آن‌ها
    از شبکه عمومی عبور نمی‌کند.
-   ساخت `telegram-bot-api` از سورس ممکن است حدود ۵ تا ۱۵ دقیقه به زمان
    Build اضافه کند.
-   اگر متغیرهای API را تنظیم نکنید، ربات از سرور رسمی تلگرام استفاده
    می‌کند.

### استفاده از فایل local_secrets.sh

در صورت نیاز می‌توانید مقادیر را در فایلی به نام `local_secrets.sh` کنار
`start.sh` قرار دهید:

``` bash
export TELEGRAM_API_ID="YOUR_API_ID"
export TELEGRAM_API_HASH="YOUR_API_HASH"
```

این فایل حاوی اطلاعات محرمانه است؛ آن را در GitHub منتشر نکنید.

## 🍪 رفع خطای کوکی و محتوای خصوصی

یوتیوب و گاهی اینستاگرام ممکن است درخواست‌های سرورهای ابری را مشکوک تشخیص
دهند و خطای زیر را نمایش دهند:

`Sign in to confirm you're not a bot`

### ساخت فایل کوکی

1.  با افزونه‌ای مانند **Get cookies.txt LOCALLY** و در حالی که در سایت
    وارد حساب شده‌اید، فایل `cookies.txt` را Export کنید.
2.  برای اجرای محلی، مسیر فایل را در `COOKIES_FILE` قرار دهید.
3.  برای Railway، محتوای فایل را Base64 کنید و خروجی را در
    `COOKIES_FILE_B64` قرار دهید.

Linux / macOS:

``` bash
base64 -w0 cookies.txt
```

Windows PowerShell:

``` powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cookies.txt"))
```

ربات ابتدا هر درخواست را بدون کوکی امتحان می‌کند و فقط در صورت دریافت
خطای مشخص ورود، یک‌بار با کوکی دوباره تلاش می‌کند.

> ⚠️ کوکی‌ها اطلاعات حساس حساب شما را در خود دارند. فایل `cookies.txt` یا
> مقدار آن را در کد یا GitHub قرار ندهید. کوکی‌ها ممکن است منقضی شوند و
> نیاز به Export مجدد داشته باشند.

## 🔧 رفع خطاهای رایج

### `The page needs to be reloaded`

نسخه‌های جدید یوتیوب ممکن است به JavaScript Runtime نیاز داشته باشند.
پروژه از `yt-dlp[default]` و پکیج `deno` استفاده می‌کند.

-   آخرین `requirements.txt` را دریافت و Push کنید.
-   روی Railway یک Redeploy بدون استفاده از کش قدیمی انجام دهید.
-   در Build Logs نصب موفق `deno` و `yt-dlp` را بررسی کنید.

### `HTTP Error 403: Forbidden`

این خطا معمولاً به IP سرور، کوکی منقضی‌شده یا نیاز به PO Token مربوط است.
ربات به‌ترتیب این روش‌ها را امتحان می‌کند:

1.  دریافت بدون کوکی
2.  دریافت با کوکی، در صورت تنظیم بودن `COOKIES_FILE_B64`
3.  استفاده از کلاینت جایگزین `android_vr`

اگر خطا ادامه داشت، کوکی را تازه کنید و در Logs نسخه `yt-dlp` و وضعیت
نصب Deno را بررسی کنید. در برخی شرایط ممکن است به پراکسی/IP مناسب یا
PO-Token provider نیاز باشد.

### خطای FFmpeg

1.  بررسی کنید `Dockerfile` در ریپو وجود داشته و Push شده باشد.
2.  در Railway بخش **Settings → Build** را باز کنید.
3.  Builder را روی **Dockerfile** قرار دهید.
4.  یک Redeploy انجام دهید.
5.  در Build Logs دنبال پیام نصب FFmpeg بگردید.

### به‌روزرسانی yt-dlp

ساختار سایت‌ها مرتب تغییر می‌کند. برای به‌روزرسانی:

``` bash
pip install -U "yt-dlp[default]"
```

## 🚀 دیپلوی روی Railway

پروژه دارای `Dockerfile` است تا نصب FFmpeg و ساخت Local Bot API با روش
قابل اطمینان‌تری انجام شود.

1.  ریپو را در GitHub ایجاد و کد را Push کنید.
2.  وارد [Railway](https://railway.app) شوید و با GitHub وارد شوید.
3.  گزینه **New Project → Deploy from GitHub repo** را انتخاب کنید.
4.  ریپوی پروژه را انتخاب کنید.
5.  مطمئن شوید Builder روی **Dockerfile** است.
6.  در بخش **Variables**، حداقل `TELEGRAM_BOT_TOKEN` را تنظیم کنید.
7.  در صورت نیاز متغیرهای اختیاری را نیز اضافه کنید.
8.  پس از پایان Deploy، در Logs پیام «ربات در حال اجراست...» را بررسی
    کنید.

ربات از Polling استفاده می‌کند؛ بنابراین به دامنه یا پورت عمومی نیاز
ندارد. فایل `Procfile` نیز دستور اجرای Worker را برای محیط‌های سازگار
مشخص می‌کند:

``` text
worker: python bot.py
```

### نکات Railway

-   پلن رایگان Railway ممکن است برای اجرای ۲۴/۷ کافی نباشد.
-   فایل‌های دانلودشده پس از ارسال پاک می‌شوند تا فضای دیسک موقت اشغال
    نشود.
-   هر Push به Branch اصلی می‌تواند باعث Deploy خودکار شود.
-   برای فایل‌های بزرگ، محدودیت فضای دیسک موقت سرویس را در نظر بگیرید.
