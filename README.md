## 🚀 نصب و اجرا

ابتدا مخزن را دریافت کن:

```bash
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
```

محیط مجازی بساز و فعالش کن:

```bash
python -m venv venv
```

در Linux و macOS:

```bash
source venv/bin/activate
```

در Windows PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

وابستگی‌ها را نصب کن:

```bash
pip install -r requirements.txt
```

توکن ربات را تنظیم و برنامه را اجرا کن:

```bash
export TELEGRAM_BOT_TOKEN="YOUR_BOT_TOKEN"
python bot.py
```

در Windows PowerShell:

```powershell
$env:TELEGRAM_BOT_TOKEN="YOUR_BOT_TOKEN"
python bot.py
```

> نام `USERNAME/REPOSITORY` را با آدرس مخزن خودت جایگزین کن.

## ⚙️ تنظیم متغیرهای محیطی

متغیرهای اصلی و اختیاری:

| متغیر | کاربرد | وضعیت |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن ربات تلگرام | ضروری |
| `GEMINI_API_KEY` | کمک به تشخیص نام آهنگ از عنوان و کپشن | اختیاری |
| `AUDD_API_KEY` | تشخیص آهنگ با سرویس AudD | اختیاری |
| `ACR_HOST` | آدرس میزبان پروژه ACRCloud | اختیاری |
| `ACR_ACCESS_KEY` | کلید دسترسی ACRCloud | اختیاری |
| `ACR_ACCESS_SECRET` | کلید محرمانه ACRCloud | اختیاری |
| `TELEGRAM_API_ID` | شناسه API تلگرام برای Local Bot API | اختیاری |
| `TELEGRAM_API_HASH` | هش API تلگرام برای Local Bot API | اختیاری |
| `COOKIES_FILE` | مسیر فایل کوکی در محیط محلی | اختیاری |
| `COOKIES_FILE_B64` | محتوای Base64 فایل کوکی برای محیط‌هایی مثل Railway | اختیاری |
| `REQUEST_COOLDOWN_SECONDS` | فاصلهٔ زمانی بین درخواست‌های کاربر | اختیاری؛ پیش‌فرض ۲۰ ثانیه |

کلیدها را در کد قرار نده و آن‌ها را در مخزن Git آپلود نکن. در محیط استقرار، از بخش Variables یا Environment Variables استفاده کن.

## 🎵 جست‌وجو و دانلود موزیک

بخش جست‌وجوی موزیک ابتدا YouTube Music را بررسی می‌کند:

- می‌توانی نام آهنگ یا فقط نام خواننده را جست‌وجو کنی.
- نتایج در صفحه‌های ۱۰تایی نمایش داده می‌شوند.
- اگر نتیجه‌ای پیدا نشود، امکان جست‌وجو در YouTube معمولی هم ارائه می‌شود.
- در حالت عادی نسخهٔ رسمی آهنگ نسبت به ریمیکس، کاور یا اجرای زنده اولویت دارد؛ مگر اینکه خودت همان نسخه‌ها را جست‌وجو کنی.

**نکته درباره Spotify:** دانلود مستقیم از Spotify پشتیبانی نمی‌شود؛ چون محتوای آن تحت DRM قرار دارد. برای دریافت آهنگ می‌توان از منابعی مانند YouTube یا SoundCloud استفاده کرد.

### تشخیص آهنگ از روی ویدیو

اگر یک فایل ویدیویی برای ربات بفرستی، قابلیت‌های زیر در دسترس‌اند:

1. استخراج صدای ویدیو و ساخت فایل MP3
2. بررسی اطلاعات و عنوان ویدیو
3. تحلیل عنوان یا کپشن با Gemini، در صورت تنظیم کلید API
4. بررسی بخش‌هایی از صدای ویدیو، از جمله ابتدا و میانه، با AudD یا ACRCloud
5. تلاش برای پیدا کردن نسخهٔ رسمی آهنگ و ارسال آن در کنار ویدیو

اگر آهنگ شناسایی نشود، ربات می‌تواند نام هنرمند یا اطلاعات موجود را نمایش دهد. تگ‌های فایل صوتی نیز تا حد امکان تمیز و مرتب تنظیم می‌شوند.

### سرویس‌های اختیاری تشخیص موزیک

- **Gemini:** دریافت کلید از [Google AI Studio](https://aistudio.google.com/) و تنظیم `GEMINI_API_KEY`
- **AudD:** دریافت کلید از [داشبورد AudD](https://dashboard.audd.io/) و تنظیم `AUDD_API_KEY`
- **ACRCloud:** ساخت پروژه از نوع Audio & Video Recognition در [کنسول ACRCloud](https://console.acrcloud.com/) و تنظیم `ACR_HOST`، `ACR_ACCESS_KEY` و `ACR_ACCESS_SECRET`

هیچ‌کدام از این سرویس‌ها برای اجرای پایهٔ ربات اجباری نیستند.

## 📃 دانلود پلی‌لیست یوتیوب

در صورت ارسال لینک پلی‌لیست یوتیوب:

- اطلاعات پلی‌لیست و تصویر آن نمایش داده می‌شود.
- ویدیوها در صفحه‌های ۵تایی فهرست می‌شوند.
- ویدیوهای خصوصی یا حذف‌شده نادیده گرفته می‌شوند.
- حداکثر ۳۰۰ ویدیوی اول بررسی می‌شوند.
- با انتخاب هر مورد، همان ویدیو برای دانلود انتخاب می‌شود.

> اگر لینک یک ویدیوی یوتیوب را همراه پارامتر `&list` بفرستی، ربات آن را به‌عنوان همان ویدیوی انتخاب‌شده در نظر می‌گیرد، نه دانلود خودکار کل پلی‌لیست.

## 📦 ارسال فایل‌های حجیم با Local Bot API

سرور رسمی Telegram Bot API برای دریافت فایل توسط ربات محدودیت ۲۰ مگابایت دارد. برای کار با فایل‌های بزرگ‌تر، پروژه امکان استفاده از Local Bot API را در Docker فراهم می‌کند.

با تنظیم متغیرهای زیر، حالت Local Bot API فعال می‌شود:

```env
TELEGRAM_API_ID=YOUR_API_ID
TELEGRAM_API_HASH=YOUR_API_HASH
```

این اطلاعات را از بخش [API Development Tools تلگرام](https://my.telegram.org/) دریافت کن.

### رفتار حالت محلی

- سرور Local Bot API در فرایند Docker از سورس ساخته و اجرا می‌شود.
- در صورت سالم بودن سرور محلی، ربات از آن استفاده می‌کند و از نشست API ابری خارج می‌شود.
- اگر راه‌اندازی Local Bot API موفق نباشد، ربات به API رسمی برمی‌گردد.
- پس از خروج از API ابری، در صورت شکست حالت محلی، تا ۱۰ دقیقه امکان تلاش مجدد برای استفاده از API ابری وجود ندارد.
- در حالت محلی، مسیر فایل روی دیسک به سرور داده می‌شود و لازم نیست کل فایل از طریق HTTP منتقل شود.
- برای عملیات ارسال، مهلت زمانی ۳۰ دقیقه‌ای در نظر گرفته شده است.
- درخواست‌های هم‌زمان پشتیبانی می‌شوند.
- در این حالت محدودیت فایل می‌تواند تا ۲ گیگابایت باشد.

ساخت Local Bot API ممکن است حدود ۵ تا ۱۵ دقیقه طول بکشد. هر دو سرویس باید در یک کانتینر و روی شبکهٔ محلی در دسترس باشند.

اگر متغیرهای `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را تنظیم نکنی، ربات از API رسمی استفاده می‌کند؛ در این حالت محدودیت ارسال فایل ۵۰ مگابایت است.

> می‌توانی اطلاعات حساس را در فایل محلی مانند `local_secrets.sh` نگه داری، اما این فایل را هرگز وارد Git نکن.

## 🍪 کوکی ویدیوهای محدودشده

برای برخی ویدیوهای یوتیوب ممکن است احراز هویت لازم باشد. در این شرایط می‌توانی فایل `cookies.txt` را از مرورگر خودت استخراج کنی.

### اجرای محلی

مسیر فایل را تنظیم کن:

```env
COOKIES_FILE=/path/to/cookies.txt
```

### اجرای روی Railway

محتوای فایل را به Base64 تبدیل کن و خروجی را در متغیر `COOKIES_FILE_B64` قرار بده.

در Linux و macOS:

```bash
base64 -w0 cookies.txt
```

در PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cookies.txt"))
```

ربات ابتدا بدون کوکی تلاش می‌کند و فقط در صورت مواجهه با چالش ورود یا احراز هویت، تلاش مجدد با کوکی را انجام می‌دهد.

**هشدار امنیتی:** فایل کوکی ممکن است دسترسی حساب کاربری‌ات را در اختیار دیگران قرار دهد. آن را با هیچ‌کس به اشتراک نگذار، در Git آپلود نکن و در صورت افشای آن، نشست‌های مربوط را باطل کن. کوکی‌ها ممکن است پس از مدتی منقضی شوند و نیاز به استخراج مجدد داشته باشند.

## 🛡️ محدودیت درخواست‌ها

برای جلوگیری از اسپم، ربات به‌صورت پیش‌فرض بین درخواست‌های هر کاربر ۲۰ ثانیه فاصله در نظر می‌گیرد.

- شمارندهٔ پیام درخواست و شمارندهٔ شروع عملیات جداگانه مدیریت می‌شوند.
- جابه‌جایی بین صفحه‌ها و دکمهٔ پایان، تایمر درخواست جدید را فعال نمی‌کنند.
- مقدار را می‌توان با متغیر `REQUEST_COOLDOWN_SECONDS` تغییر داد.
- با تنظیم مقدار `0` محدودیت زمانی غیرفعال می‌شود.

## 🧹 پاک‌سازی پیام‌ها پس از ارسال

پس از ارسال موفق فایل:

- پیام وضعیت ربات پاک می‌شود.
- پیام حاوی لینک ارسال‌شده توسط کاربر نیز پاک می‌شود.
- دکمهٔ 🔗 لینک زیر فایل قرار می‌گیرد.

اگر ارسال فایل با خطا مواجه شود، پیام‌ها پاک نمی‌شوند تا کاربر بتواند خطا را ببیند.

برای پاک کردن پیام کاربران در گروه، ربات باید دسترسی ادمین و مجوز حذف پیام‌ها را داشته باشد.

## 🚄 استقرار روی Railway

پروژه با Docker آمادهٔ استقرار روی [Railway](https://railway.app/) است.

1. مخزن را در GitHub قرار بده.
2. در Railway یک پروژهٔ جدید بساز و مخزن GitHub را متصل کن.
3. روش ساخت را روی Dockerfile قرار بده.
4. متغیرهای محیطی موردنیاز را در بخش Variables وارد کن.
5. سرویس را Deploy کن و لاگ‌ها را بررسی کن.

از آنجا که ربات با روش polling کار می‌کند، نیازی به دامنه یا تنظیم پورت عمومی نیست.

### اجرای Worker با Procfile

در صورت استفاده از محیطی که Procfile را می‌خواند، محتوای فایل می‌تواند این باشد:

```procfile
worker: python bot.py
```

پس از اجرای موفق، باید پیامی مشابه `ربات در حال اجراست...` در لاگ‌ها ببینی.

### نکات استقرار

- فایل `Dockerfile` برای نصب وابستگی‌ها و اجرای ربات استفاده می‌شود.
- اسکریپت `start.sh` راه‌اندازی ربات و Local Bot API را مدیریت می‌کند.
- فایل‌های موقت پس از پایان کار با `shutil.rmtree` پاک‌سازی می‌شوند.
- با اتصال مخزن به Railway، می‌توانی استقرار خودکار برای شاخهٔ `main` را فعال کنی.
- محدودیت‌های پلن رایگان Railway ممکن است روی زمان اجرا و منابع در دسترس اثر بگذارد.

## 🧯 رفع خطاهای رایج

### خطای Deno یا پیام `The page needs to be reloaded`

نسخه‌های جدید yt-dlp برای برخی استخراج‌های YouTube به JavaScript runtime نیاز دارند. مطمئن شو وابستگی‌های زیر نصب شده‌اند:

```bash
pip install -U "yt-dlp[default]"
```

همچنین Deno باید نصب و در دسترس باشد. پس از تغییر وابستگی‌ها، پروژه را با Build بدون کش دوباره Deploy کن.

### خطای 403 یا محدودیت دسترسی YouTube

به‌ترتیب این موارد را بررسی کن:

1. ابتدا بدون کوکی امتحان کن.
2. اگر ویدیو نیاز به ورود دارد، کوکی معتبر تنظیم کن.
3. در صورت پشتیبانی نسخهٔ yt-dlp، روش استخراج `android_vr` را بررسی کن.
4. لاگ‌ها را برای خطاهای مربوط به Deno و احراز هویت بررسی کن.
5. کوکی منقضی‌شده را دوباره استخراج کن.

در بعضی شرایط محدودیت‌های شبکه یا نیاز به Residential Proxy و سرویس‌دهندهٔ PO Token نیز ممکن است مطرح باشد.

### به‌روزرسانی yt-dlp

```bash
pip install -U "yt-dlp[default]"
```

پس از به‌روزرسانی، ربات را دوباره اجرا یا Deploy کن.

### مشکل FFmpeg

مطمئن شو FFmpeg نصب شده و دستورهای `ffmpeg` و `ffprobe` در PATH سیستم قابل اجرا هستند:

```bash
ffmpeg -version
ffprobe -version
```
